# Reactor Server —— 基于 epoll 的单 Reactor 多线程 TCP 服务器

一个在 Linux 上从零实现的轻量级 TCP 服务器：**单 Reactor（epoll ET）+ 线程池业务处理**架构，
内置长度协议拆包、异步写回、心跳保活、并发上限与优雅关闭，配套完整的协议测试客户端。
纯 C 实现，仅依赖 pthread，无第三方库。

## 架构总览

```
                        ┌────────────────────────────────────────────┐
                        │              epoll 主线程（Reactor）         │
 客户端 ──TCP──► listen_fd ─► on_accept ─► Conn(rbuf/wbuf)             │
                        │      ▲                    │ EPOLLIN        │
                        │      │                    ▼                │
                        │  EPOLLIN            on_read → rbuf         │
                        │                         │                  │
                        │                  parse_packet（4字节长度头拆包）│
                        │                         │ 完整包            │
                        └─────────────────────────┼──────────────────┘
                                                  ▼
                        ┌────────────────────────────────────────────┐
                        │        线程池（4工作线程，环形任务队列）        │
                        │   handle_packet：业务处理（当前为echo）        │
                        │        │ 回包入队（互斥锁）+ 写eventfd唤醒      │
                        └────────┼───────────────────────────────────┘
                                 ▼
                        ┌────────────────────────────────────────────┐
                        │  on_wakeup：按conn_id定位连接 → 写wbuf        │
                        │  conn_flush：writev直发；发不完挂EPOLLOUT续发   │
                        └────────────────────────────────────────────┘
 辅助组件：异步日志（专用线程写盘）｜心跳扫描（主循环周期遍历）｜信号优雅关闭
```

**线程边界（核心设计约束）**：Conn、epoll、fd 只允许主线程操作；工作线程通过
"回包队列（互斥锁保护）+ eventfd 唤醒"与主线程通信，回包只携带连接唯一 ID 不携带裸指针，
连接已关闭时按 ID 查不到即安全丢弃，杜绝 use-after-free。

## 功能特性

- **epoll ET 主框架**：accept/read/write 全部循环处理到 EAGAIN，非阻塞 IO
- **长度协议拆包**：4 字节大端长度头 + 包体，环形缓冲缓存半包、while 循环连续拆粘包，非法长度直接断连
- **线程池业务解耦**：生产者-消费者模型，耗时业务不阻塞 epoll 主线程
- **EPOLLOUT 异步写回**：写环形缓冲 + writev 零拷贝发送（回绕数据两段一次发出），内核缓冲满挂 EPOLLOUT 续发，发空摘除
- **心跳超时检测**：主循环周期扫描连接链表，清理长时间无数据的僵死连接（无需每连接定时器）
- **最大连接数限制**：超限新连接 accept 后立即拒绝，不分配资源
- **信号处理 + 优雅关闭**：SIGINT/SIGTERM 只置标记；关闭顺序"线程池排空 → 服务器释放 → 日志冲刷"，不丢任务、不丢日志、无泄漏
- **异步日志**：业务调用非阻塞入队，专用线程写盘，磁盘 IO 不影响主循环
- **配套测试客户端**：basic/sticky/half/big 四种模式覆盖正常收发、粘包、半包、大包场景

## 目录结构

```
├── main.c          入口：组件装配 + 优雅关闭编排
├── server.h/.c     服务器核心：epoll框架、连接管理、拆包、写回、心跳、信号
├── ringbuffer.h/.c 环形缓冲区：收发缓存，peek预读支持拆包
├── threadpool.h/.c 线程池：任务队列 + 优雅排空关闭
├── async_log.h/.c  异步日志：入队即返回，专用线程写盘
├── client.c        协议测试客户端（basic/sticky/half/big/all）
└── Makefile        编译目标
```

## 编译与运行

环境：Linux（Ubuntu 验证），gcc，pthread。

```bash
make main        # 编译服务器
make client      # 编译测试客户端

# 终端1：启动服务器（监听8888端口，日志写入server.log）
./main

# 终端2：运行测试
./client all     # 依次跑 basic/sticky/half/big 全部场景
./client sticky  # 也可单独跑某个模式
```

停止服务器：Ctrl+C 或 `kill <pid>`，进程会优雅退出并打印 `server exited gracefully`。

## 通信协议

```
+----------------+--------------------+
| 4字节长度头     | 包体（长度=头部的值） |
| 大端 uint32    | 0 ~ 1MB            |
+----------------+--------------------+
```

- 长度头只计包体字节数，不含自身 4 字节
- 包体超过 1MB 视为协议错误，服务器断开连接
- 当前业务为 echo：服务器原样回包（包头+包体完全一致）

## 关键配置（server.h）

| 宏 | 默认值 | 说明 |
|----|--------|------|
| LISTEN_PORT | 8888 | 监听端口 |
| MAX_EVENTS | 1024 | epoll_wait 单次最大事件数 |
| MAX_PKG_BODY_LEN | 1MB | 包体上限，超限断连 |
| CONN_BUF_SIZE | 4096 | 每连接读/写环形缓冲大小 |
| MAX_CONN_NUM | 1024 | 最大并发连接数 |
| HEARTBEAT_TIMEOUT | 60s | 无数据超时阈值 |
| HEARTBEAT_CHECK_SEC | 5s | 心跳扫描周期 |

注意：单包总长（4+包体）不能超过 CONN_BUF_SIZE，否则读缓冲写满会断连；
如需支持大包，调大该宏（线程池队列容量在 main.c 中配置，默认 4 线程/队列 8）。

## 设计要点

1. **ET 模式的正确姿势**：所有 fd 非阻塞，accept/read/write 循环到 EAGAIN；
   EPOLLOUT 只在写缓冲有积压时注册，发空即摘，避免无意义触发。
2. **跨线程回包的生命周期安全**：连接用单调递增 conn_id 标识（fd 复用不撞 ID），
   回包按 ID 在活跃链表查找，连接已关闭则丢弃——工作线程永远不持有 Conn 裸指针。
3. **writev 零拷贝发送**：环形缓冲回绕数据直接构造两段 iovec 一次发出，
   不做"拷到临时缓冲再 send"的额外拷贝。
4. **心跳不用定时器**：epoll_wait 超时设为"距下次扫描的差值"，静默期也能按时醒来，
   扫描用二级指针遍历链表，关闭节点后安全推进。
5. **优雅关闭的顺序**：信号处理函数只写 volatile sig_atomic_t 标记（异步信号安全）；
   主循环退出后先 threadpool_destroy（等队列排空+在途任务清零+join 全部线程），
   再 server_destroy，最后 log_destroy——保证释放资源时已无任何并发访问。
6. **SIGPIPE 防护**：忽略 SIGPIPE，向已关闭连接写返回 EPIPE 由代码正常处理，进程不会被信号杀死。

## 已知限制

- 单 Reactor 架构：所有 IO 在一个线程，适合学习/中小并发；更高并发可演进为主从 Reactor
- 线程池任务乱序：多线程并发处理时回包顺序不保证与请求顺序一致（echo 场景按内容比对不受影响）
- 心跳为"收到任意数据即活跃"，未定义专用心跳包类型
- 日志队列满时丢弃新日志（保业务优先的简单策略）
